# v1.0 readiness gate

Status: gate definition only. This document does **not** authorize a `v1.0` tag, institutional
readiness, public deployment, or calendar commitment.

## Governing rule

v1.0 is a gate, not a date. Software must not set `release_authorized=true` or claim institutional
readiness because CI is green or because this checklist exists.

## Required independent reviews

- Security review (threat model coverage, pen-test, supply-chain)
- Usability review
- Accessibility review
- Evaluation / assessment-validation review against the frozen protocol

## Required ownership and sustainability

- Named maintenance ownership
- Funding / continuity plan
- Stable public `/v1` API and migration policy
- Contributor guide for adding: source universe, adapter, assertion predicate, entity kind, delta operation

## Required engineering evidence

- Upgrade tests from every supported release/schema version
- One-command offline reference flow: discovery → proposal → adjudication → release-candidate, no network
- Hosted CI with executed steps and logs (empty `steps: []` is infrastructure failure, not pass)
- Public S2 releases pass protected-data scan
- No critical/high exploitable finding open for pilot

## Explicitly withheld by this document

- Git tag `v1.0`
- Institutional pilot clearance
- Aggregate NeuroAI score
- Auto-authorization from mechanical PASS
- Authentication bolted onto local `ThreadingHTTPServer` as institutional deployment
