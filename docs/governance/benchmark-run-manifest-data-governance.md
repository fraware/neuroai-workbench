# Benchmark run manifest data governance

Benchmark freeze and held-out run manifests are control metadata. They must not contain held-out item identifiers, item-level human dispositions, reviewer records, rationales, adjudication packets, HMAC secrets, licensed source bytes, model prompts containing controlled labels, or personal reviewer information beyond a bounded role/reference needed for attributable operations.

Private benchmark membership, item-level dispositions, review records, sampling records, coverage reports, exposure registers, rights-review material, and commitment secrets remain in S3-controlled research storage. The v0.2 freeze manifest contains only opaque commitments, aggregate boundary-disposition counts, protocol/report digests, and non-sensitive control references. A public run manifest contains artifact digests and aggregate-result commitments. At PRE-G2, `AGGREGATE_ONLY` is the only permitted run-export policy.

The v0.2 freeze record is checked against the exact `FROZEN_COMMITMENTS_ONLY` D3/D4 public contract. It binds the public-contract digest, approved D1 digest, exact attributable G1 disposition, membership/disposition commitments, required D1 boundary coverage, required patent/product strata, human-review provenance digest, adjudication-accounting digest, sampling protocol, contamination/exposure state, and rights-review reference. The required human-review field names are public contract metadata; the corresponding item-level values remain S3.

The rights-containment declaration `S3_CONTROLLED_NO_REDISTRIBUTION_AUTHORITY_CLAIMED` is intentionally non-authorizing. A structurally valid manifest does not establish licence rights, lawful basis, redistribution permission, reviewer consent, confidentiality sufficiency, or substantive source-data compliance. In particular, protected/licensed source material remains subject to its separate rights review and cannot acquire publication authority from a benchmark manifest.

A successor freeze preserves predecessor identity through `predecessor_manifest_sha256`; changed membership, dispositions, protocols, or bound evidence therefore receive a new manifest identity instead of silently replacing the earlier freeze. Evaluation runs bind the exact freeze/public-contract pair plus Workbench commit, pipeline/configuration, threshold policy, abstention policy, subgroup plan, metric/projection identity, predictions, and aggregate results.

Software validation establishes structure and exact bindings only. It does not establish scientific representativeness, adjudicator competence or independence, factual label correctness, absence of undisclosed contamination, statistical sufficiency, G2 passage, S2 authority, publication authority, or v4.2 assessment effects.
