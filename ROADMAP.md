# Roadmap

## v0.2.1 — repository stabilization

- Centralized version identity and release metadata.
- Source-tree hygiene and reproducible build separation.
- Branch governance, CODEOWNERS, issue templates, and pull-request controls.
- Repository contribution and operating rules.
- Distinct CI, package, container, security, and release-verification gates.

## v0.3.0 — collaborative assessment operations

Implemented foundations:

- Deterministic human-readable assessment reports.
- Controlled assistance export/import, human disposition, provenance, and exact accepted-proposal application.
- PRIMA v4.2 reference adaptation with explicit loss boundaries.
- Observatory successor validation, import, summary, and reopening queue.
- Role-aware local review assignments, disagreement, scoped dispositions, appeals, dissent preservation, and integrity verification.
- Append-only assignment revocation and supersession lineage.
- Protected-evidence metadata requests and out-of-band holder-response records without raw-byte transfer.
- Deterministic accessibility regression protection and presentation internationalization architecture.
- Byte-reproducible XLSX, DOCX, and PDF products.
- Integrity-addressed review-state snapshots.
- Proportional default release attestation with typed `AUTHORIZE` / `WITHHOLD` decisions and an optional high-assurance governance profile.

Remaining external validation and release work:

- Independent linguistic validation for any non-English locale before publication of that locale.
- Representative-user and assistive-technology accessibility validation.
- Independent empirical validation of assessment interpretation, calibration, and decision usefulness.
- A separate explicit software release action for `v0.3.0` when selected.

## v0.4.0 — institutional pilot architecture

- Separate authenticated deployment profile.
- Encryption at rest and institutional key-management design.
- Signed manifests and disclosure-control workflows.
- Federated evidence requests.
- Backup, recovery, retention, deletion, and legal-hold controls.
- Multi-institution pilot protocol and external security/privacy review.

The institutional profile should be driven by concrete pilot requirements. The local offline-first reference profile remains separate.

## v1.0 readiness gates

- Independent security assessment.
- External usability and accessibility evaluation.
- Empirical validation across materially different NeuroAI contexts.
- Controlled multi-country pilot evidence.
- Documented participant and affected-community review.
- Stable API and migration policy.
- Long-term maintenance and incident-response capacity.

The roadmap does not imply funding, institutional adoption, regulatory recognition, conformance, or endorsement by any external institution.
